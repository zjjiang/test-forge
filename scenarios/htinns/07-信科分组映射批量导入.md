# 信科分组映射批量导入 业务描述

> 用户场景 7（2026-11-06 定义）：价格维护 · 配置页（/maintain/config）的 xlsx 批量导入全链路，参考老平台（htinns-server `_archived` xk_rate_config 同语义）。

## 环节

1. **店侧基线登录**：复用固定夹具店 E2E-批量-1105-160745（shop_id=125，密码 123456）
2. **配置页基线**：打开 /maintain/config，表格渲染（基线映射数不作门禁——整店替换语义使起点无关）
3. **批量导入 5 行真实映射**：批量添加弹窗上传 `ratemap-import-5.xlsx`（rate -35~-31 → tag 4901~4897）→ flash「导入完成：5 行」
4. **列表验证**：恰 5 行；首行 = 文件末行 -31/4897（列表按 id 倒序，最后导入的行在最上）；全部「启用」
5. **整店替换再导入 3 行**：上传不同 3 行文件 → 恰 3 行、旧 tag（4901/4897）全部消失——**导入是整店替换不是追加**（老平台 handlers 同语义）
6. **非法表头拒绝**：上传「比例/分组/启停」表头的 xlsx → flash「导入失败：表头须为 rate/tag_id/is_active」，原 3 行数据零破坏
7. **导出 xlsx 落盘**：`xk_rate_config_shop125.xlsx`（文件名含店号，导出/导入可直接闭环）
8. **收尾清空**（teardown）：导入仅表头的空 xlsx →「导入完成：0 行」→ 列表回到「暂无映射」

## 数据纪律（v4）

- 复用夹具店 125，不新增店铺；xlsx 行数据取自**生产库 shop 10 的真实 rate→tag_id 映射**（不是编造值）
- 写操作只发生在夹具店内；收尾导入空表清空，下次运行从空店重建
- 夹具目录放项目变量 `RATEMAP_ASSETS`（路径即配置，换文件=换数据，与 IMPORT_XLSX 同口径）

## 口径备注（源码核实，ratemap.py import_xlsx）

- 表头必须恰为 `rate/tag_id/is_active`（小写、顺序一致），否则整文件拒绝
- 导入 = **先删后插单事务**：任一行非法（rate 非整数 / tag_id 空）整体拒绝，旧数据不破坏
- rate 为整数（可负）；tag_id 非空字符串；is_active 0/1
- 列表页 20 条/页，按 id 倒序；弹窗提交带 confirm（整店替换二次确认），runner 以 accept 处理
- 语义「改映射即改下次推送走的标签」——本场景只测映射配置面，推送链路属④推送域

筛选/抓价/算价/推送等价格维护其余工序不在本场景；安全越权（跨店导入/导出）在场景 06 模式下如有需要另立。
