# 店铺停用闭环 业务描述

> 用户场景 2（2026-11-04 定义）：验证「停用店铺」开关对店侧登录的实际效力。

## 环节

1. **管理员登录并新增E2E店**：admin 登录，新增一个 E2E 测试店作为本次测试对象（不碰真实店）
2. **店侧基线登录**：停用前，该店账号可正常登录（建立基线）
3. **admin停用店铺**：店铺列表行内停用，flash 提示「已停用」，状态翻转为「停用」
4. **停用后登录被拒**：店侧重新登录 → 失败，提示「用户名或密码错误」，留在登录页
5. **admin启用店铺**：行内启用，flash 提示「已启用」，状态翻回「在营」
6. **启用后登录恢复**：同一账号重新登录 → 成功进入平台

## 边界与说明

- **测试对象**：每次运行新建 `E2E-停用-<时间戳>` 店，运行结束停用留档；真实店（新乡旅途 shop_id=7）只读不碰
- **停用店登录的提示口径**：源码中登录查询按 `is_active=True` 过滤，停用店与密码错误返回同样的「用户名或密码错误」（安全上不暴露账号存在性，属于合理设计）
- **停用的额外效果**（模板注明，本场景不展开）：停用店从各页面下拉消失；管理员账户不可停用
- 新店默认密码 123456（adddlg 密码留空）
