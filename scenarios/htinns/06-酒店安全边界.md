# 酒店安全边界 业务描述

> 用户场景 5 的安全部分，拆成独立哨兵场景（2026-11-05）：专职盯防越权与非法输入，不与日常主链路混跑——哨兵红了单独处理，不污染主场景红绿灯。

## 环节

1. **管理员登录并新增E2E店** / **店侧登录并备夹具酒店**：夹具 1 家带 SHID 酒店，先打上「白名单」标签（供非法提交后比对不变）
2. **越权编辑他店酒店被404**：店侧会话直接 POST `/hotels/<他店酒店id>/update`（目标为新乡旅途真实酒店，id 走项目变量 `OTHER_HOTEL_ID`）→ 期望 **404**，不泄露他店酒店存在性；只读探测，绝不写真实店
3. **非法标签值被拒**：POST `/hotels/tag` 带 `status_tag=恶意标签<script>` → 期望 **302** 回列表 + danger flash「非法status_tag: …」→ 夹具酒店标签仍为白名单（非法提交不落库）

## 口径备注（源码核实）

- 越权编辑：`_shop_hotel_or_404` / `update_hotel` 中「不存在或不属本店一律 404」
- 打标校验：`tag_service._validate` → `ValueError("非法status_tag: %s")` → flash danger
- 两个 http 探测复用 shop actor 登录态 cookie（`http` 步骤原生支持）
