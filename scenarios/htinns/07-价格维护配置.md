## 标签设置（/maintain/config，信科分组映射）

源码口径（`maintain_views.py config_import` + `ratemap.py import_xlsx`）：

1. **表头校验**：必须恰为 `rate/tag_id/is_active`（小写、顺序一致），否则整文件拒绝，
   flash「导入失败：表头须为…」。
2. **整店替换**：先删后插、单事务——任一行非法整体拒绝，旧数据零破坏；不是追加。
3. **列表 id 倒序**：最后导入的一行显示在最上，首行断言用文件末行（-31/4897）。
4. xlsx 行数据取自生产 shop 10 真实映射（-35~-31→4901~4897、100/20/19→5134/4912/4911），不是编造值。
5. 导出 `xk_rate_config_shop<id>.xlsx` 可直接回导（导出/导入闭环）。

## 水位设置（/maintain/config/watermark，specs v2/price-timeliness-loop）

2026-11-07 拍板的配置 UI：

- **权限**：admin 可拨任意白名单店；非 admin 拨自己店（仍须在白名单）。场景用夹具店账号拨本店 125。
- **两段式**：无 `confirm=1` 只渲染影响估算页（估算 = datasrc 增量流 id>目标值 的条数，只读）；
  `confirm=1` 才写库。第一段提交有浏览器 `confirm()` 弹窗（actor dialogs: accept）。
- **审计**：生效后写 `wf_step_log`（step=watermark），页面「最近拨回审计」显示
  `[水位拨回] 店 125：cur → new（操作人 …）`。
- **读回验证**：二次拨回 99999 时确认页显示 `12345 → 99999` 且无「未设置」——证明 `get()` 读回正确。
- 夹具店 125 无酒店，datasrc 增量流估算约 0 条，重放无实际影响；水位值不参与任何循环计算。

## 断言口径

- 状态徽标用 `.pill` 判断（操作按钮文字是动作不是状态：启用行的按钮显示「停用」）。
- flash 断言认「导入完成：N 行 / 导入失败：表头须为… / 水位已拨回」原文。
- 拨回三证：flash + 当前值 + 审计行，三者同时在场才算通过。
