# 酒店新增与信科同步 业务描述

> 用户场景 3（2026-11-04 定义）：酒店管理——新增单个酒店，走信科同步回填。

## 环节

1. **店侧基线登录**：夹具店账号登录成功（基线）
2. **店侧配置信科凭证**：本店编辑弹窗填信科平台 ID `499`（与凭证账号配对）+ Cookie（环境变量 `XK_COOKIE`）
3. **新增酒店并信科同步**：
   - 打开 /hotels → 点「新增酒店」→ 弹窗填酒店名称（环境变量 `HOTEL_NAME`，信科平台真实在线酒店）
   - 点「**信科同步**」→ 提示「信科同步成功，记得保存」
   - 断言字段自动回填：供应商酒店ID / 供应商 / 城市（步骤1 关键字搜索回填）+ 飞猪 SHID / HID（步骤2 平台映射补全，shopid=499 配对正确时非空）
   - 点保存 → flash「已新增酒店」（重复执行若上次收尾失败有残留则提示「已更新既有酒店」，均认可），列表恰 1 行
4. **重复添加走upsert更新**：同名再来一遍 → 保存提示「**已更新既有酒店**」，列表仍恰 1 行（源码 upsert 语义，幂等不产生重复）
5. **收尾删除夹具酒店**（teardown）：行内删除按钮清掉测试酒店并断言列表无残留

## 边界与说明

- **测试对象（v3 数据纪律）**：复用固定夹具店 `E2E-酒店-1105-160709`（shop_id=124，账号 `e2ehtl_20261105160709`，初始密码 123456），不再每次新建店；收尾用删除功能清掉测试酒店，跑完店铺酒店列表为空，下次运行从空店重建；真实店（新乡旅途 shop_id=7）只读不碰
- **HOTEL_NAME 必须是信科平台真实存在的酒店**（同步按关键字搜，取第一条命中；搜不到会报「未找到酒店」）——初值「阿依河仁义大酒店」取自 shop7 已同步数据，可在项目变量里改
- **信科两步搜索口径**（源码 xinke_client.search_hotel）：步骤1 只靠 Cookie 搜供应商酒店；步骤2 用 `shopid=xk_shop_id` 查飞猪平台映射，**配错平台 ID 只会导致 SHID/HID 留空，主流程仍算同步成功**——所以本场景把映射补全单独成一个断言
- **重复添加不需要"去掉"**：upsert 设计（同店+同 SHID 判重，无 SHID 按店+名），重复保存即更新
